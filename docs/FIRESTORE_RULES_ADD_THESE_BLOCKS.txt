RULES NOTES:
- The app queries both collections with whereEqualTo("ownerUid", signedInUid).
- This is intentionally a per-user prototype: assigning a name in the Task Board
  does not grant another Firebase account access to the task.
- Review existing users rules separately; signup writes users/{uid}, chat user list
  reads users collection, and only owners should be able to edit their own profile.
- Do not use "allow read, write: if true" in production.
- The Realtime Database -> chats is separate; do NOT paste these Firestore rules there.
- When you press Publish, you are changing live rules for that Firebase project.
  Coordinate with the team and back up the existing rules before editing.
